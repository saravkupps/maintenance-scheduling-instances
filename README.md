# Maintenance Scheduling Instances for Telecommunication Networks

This repository contains the 64 problem instances used in the computational study of:

> Bollapragada, R., Kuppusamy, S., Rao, U., and Seshadri, S. (2026).
> "Maintenance Scheduling to Reduce Outage in a Telecommunication Network."
> *Omega* (forthcoming).

The mathematical formulation, model assumptions, parameter ranges, and reporting
conventions are described in full in the paper, particularly Section 4 (Problem
Definition and Model) and Section 6 (Computational Study). This repository
provides only the **input data** for the instances; it does not include the
optimization model, solution code, or computational results.

---

## 1. Overview of the instances

The 64 instances are generated by combining four problem parameters:

| Parameter             | Values                                                  |
| --------------------- | ------------------------------------------------------- |
| Number of activities  | 10, 50, 100, 200                                        |
| Outage variability    | None (ON), Low (OL), Medium (OM), High (OH)             |
| Precedence density    | 20% (P2), 40% (P4)                                      |
| Precedence delay      | Low = 2 hours (DL), High = 4 hours (DH)                 |

This gives 4 × 4 × 2 × 2 = **64 instances**, one per parameter combination.

Outage variability levels follow the paper's Section 6.1:

- **None (ON):** fixed outage of 3.5 minutes for every activity
- **Low (OL):** outage of 3 or 4 minutes, equal probability
- **Medium (OM):** outage uniformly distributed over {2, 3, 4, 5} minutes
- **High (OH):** outage uniformly distributed over {1, 2, 3, 4, 5, 6} minutes

---

## 2. File naming convention

Each instance is stored as one Excel workbook. File names follow the pattern:

```
{activities}_{variability}_{precedence}_{delay}.xlsx
```

For example, `200_ON_P4_DL.xlsx` is the instance with:

- 200 activities
- ON = outage variability "None" (fixed at 3.5 minutes)
- P4 = 40% of activities have a predecessor
- DL = precedence delay of 2 hours (Low)

The full code legend:

| Code | Meaning                  |
| ---- | ------------------------ |
| ON   | Outage variability None  |
| OL   | Outage variability Low   |
| OM   | Outage variability Medium|
| OH   | Outage variability High  |
| P2   | Precedence density 20%   |
| P4   | Precedence density 40%   |
| DL   | Precedence delay Low (2 h)|
| DH   | Precedence delay High (4 h)|

## 3. Workbook contents

Each Excel workbook contains three sheets.

### Sheet 1: `PrivateLines`

| Column          | Description                              |
| --------------- | ---------------------------------------- |
| PrivateLinesID  | Identifier for each private line         |

All instances use a single private line (|P| = 1), consistent with the
linear-topology setting described in Section 6.1 of the paper.

### Sheet 2: `Spans`

| Column | Description                |
| ------ | -------------------------- |
| SpanID | Identifier for each span   |

The number of spans depends on instance size, as listed in Section 6.1 of
the paper.

### Sheet 3: `ActivityData`

One row per maintenance activity, with the following columns:

| Column         | Description                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------- |
| ActivityID     | Unique activity index                                                                        |
| Duration       | Maintenance duration `Di`, in hours                                                          |
| Outage         | Network outage `Oi` caused by the activity, in minutes                                       |
| SpanID         | Span on which the activity is performed, `s(i)`                                              |
| Category       | Activity category (1 = standard); included for compatibility                                 |
| Tci            | Advance-notice requirement, in hours (72 for non-urgent activities; 0 otherwise)             |
| Predecessor    | ActivityID of the predecessor activity, or `-1` if no predecessor                            |
| Delay          | Required lag `L(i1, i2)` from predecessor completion to successor start, in hours            |
| PrivatelineID  | Private line on which the activity is performed, `P(i)`                                      |
| fi             | Penalty `φ_i` for not scheduling activity `i` within the planning horizon                    |

A `Predecessor` value of `-1` indicates that the activity has no predecessor,
and the corresponding `Delay` is `0`.

## 4. Other instance parameters

The following parameters are set globally in our computational study and are
**not** stored per-instance in the Excel files. Users who wish to reproduce
the experiments should set them as described in Section 6.1 of the paper:

| Parameter                              | Value                                                          |
| -------------------------------------- | -------------------------------------------------------------- |
| Number of private lines (|P|)          | 1                                                              |
| Planning horizon H                     | 120 (for |A|=10), 200 (for |A|=50), 400 (for |A|=100), 600 (for |A|=200) |
| Penalty φ for unscheduled activities   | 3000 (also stored in column `fi`)                              |
| Maintenance time window M              | 21:00–07:00 each day                                           |
| Advance-notice requirement (AN set)    | 72 hours (stored per activity in column `Tci`)                 |

---

## 5. Using the instances

The instances are intended to be loaded directly into the user's preferred
modeling environment (AMPL, GAMS, Pyomo, Gurobi/Python, CPLEX, etc.). To
reproduce the model used in the paper:

1. Read the three sheets from the Excel workbook (e.g., with `pandas.read_excel`).
2. Construct the mathematical formulation in Section 4.2 of the paper.
3. Set the global parameters listed in Section 4 above.
4. Solve the formulation with any MIP solver of choice.
